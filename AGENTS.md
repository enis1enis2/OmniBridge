# OmniBridge — Agent Guide

## Build & Test

```bash
mvn clean package                  # produces target/OmniBridge-1.0.0.jar
mvn test                           # run all unit tests (network tests excluded)
mvn test -Dtest=RepositoryTest     # single test class
mvn test -DexcludedGroups= -Dtest=RepositoryUrlsTest   # verify every download URL
```

Uses **Maven** (no wrapper), **Java 21**, **JUnit 5.10.2**. No mocking framework — tests are pure unit tests.

CI: GitHub Actions — `build.yml` (`mvn clean package -q`) on push to `main`/`dev` and PR to `main`. Release: tag `v*` triggers `release.yml`.

## Architecture

**Dual entry point** — the same JAR contains a Paper plugin and a minimal Velocity plugin:

| Platform | Main class | Descriptor |
|---|---|---|
| Paper | `io.omnibrige.OmniBridge` | `plugin.yml` |
| Velocity | `io.omnibrige.OmniBridgeVelocity` | `velocity-plugin.json` |

Platform detection (`PlatformDetector.detect()`): checks Velocity first, then Paper
(`io.papermc.paper.plugin.lifecycle.LifecycleEventManager` or legacy
`com.destroystokyo.paper.PaperConfig`), then Fabric (`net.fabricmc.loader.api.FabricLoader`),
then Spigot (`org.bukkit.craftbukkit.CraftServer` / `org.bukkit.Bukkit`), else `UNKNOWN`.

**Key packages:**
- `io.omnibrige.api` — public API (`OmniBridgeAPI`, events, `ViaVersionIntegration`, `GeyserIntegration`)
- `io.omnibrige.core` — `PluginManager`, `ConfigManager`, `MessageManager`, `PlatformDetector`, `PluginPresets`, `PluginDescriptions`
- `io.omnibrige.download` — `Repository` (hardcoded registry of 27 plugins), `DownloadService`
- `io.omnibrige.config` — per-plugin config generators (ViaVersion, ViaBackwards, ViaRewind, Geyser, Floodgate, ViaRewindLegacySupport)
- `io.omnibrige.commands` — `OmniBridgeCommand` (Paper), `OmniBridgeCommandVelocity`, `ChatConfigMenu`

## Key facts

- **Command base**: `/omnibrige` — aliases `ob` and `omnib` (defined in `plugin.yml`; also registered on Velocity)
- **Target platform**: Paper 1.20+ (`api-version: '1.20'`), built against Paper 1.21.4 API. Not Spigot, Folia, or Fabric.
- **Plugin registry** is in `Repository.java` (static initializer) — a `LinkedHashMap` of 27 entries with download URLs, JAR names, Bukkit names, pinned versions, install targets, and dependency mappings. Update URLs there when bumping plugin versions. When adding a new plugin, also add its description to `PluginDescriptions.java` and a config entry in `config.yml`, then update `RepositoryTest`'s expected count.
- **Install targets**: `InstallTarget.PLUGINS` → `plugins/<jarName>`; `InstallTarget.GEYSER_EXTENSIONS` → `plugins/Geyser-Spigot/extensions/<jarName>`. Use `Repository.resolveInstallPath(...)` — never build the path manually. `geyserconnect` and `thirdpartycosmetics` are extensions.
- **Versions**: `PluginInfo.version` is the version a pinned URL points at, or `null` for rolling "latest" endpoints (Geyser family, LuckPerms). `checkUpdate` compares pinned versions numerically and rolling entries by remote `Last-Modified` vs local JAR mtime, returning `UPDATE_AVAILABLE`, `UP_TO_DATE`, or `UNKNOWN`.
- **Downloads**: `DownloadService` rejects non-HTTPS URLs, caps at 128 MB, writes to a temp `.part` file, validates the ZIP header, and atomically moves over the target. A failed download never truncates an existing JAR.
- **Dependency auto-resolution**: enabling Geyser auto-enables Floodgate; enabling AuthMe also auto-enables Floodgate; DiscordSRV requires PlaceholderAPI; TuffXPlus requires ViaVersion+ViaBackwards; Hurricane requires Geyser+Floodgate; Geyser extensions require Geyser.
- **Platform compatibility**: ViaBungee only on Velocity; ProtocolLib and TuffXPlus only on Bukkit-based platforms; others universal.
- **Configs**: `config.yml` at plugin root; per-plugin configs generated by `ConfigManager` only for ViaVersion/ViaBackwards/ViaRewind/ViaRewindLegacySupport/Geyser/Floodgate. Methods in `io.omnibrige.config.*` write defaults (won't overwrite existing files). Unknown keys in `managed-plugins` are skipped with a warning.
- **Locale**: 72 YAML files in `src/main/resources/locale/`. `MessageManager` loads by locale code (e.g. `en_US`, `tr_TR`). Missing keys fall back to `en_US` per key; `msg()` never returns the raw key for a missing translation.
- **Presets**: 7 predefined bundles (`bedrock`, `full-version`, `essentials`, `server-essentials`, `max-compat`, `performance`, `chat`) in `PluginPresets.java`.
- **Events**: Custom Bukkit events (`PluginInstalledEvent`, `PluginRemovedEvent`, `PluginUpdatedEvent`) in `io.omnibrige.api.events`.
- **Reflection**: `ViaVersionIntegration` and `GeyserIntegration` target the plugins' **public interfaces** (`ViaAPI`, `UserConnection`, `ProtocolInfo`, `ProtocolVersion`, `GeyserApi`, `GeyserConnection`), not implementation classes.
- **Build artifact**: `target/OmniBridge-1.0.0.jar` (gitignored). Server install: drop into `plugins/`.
- **Velocity support is limited**: only registers a command and initializes MessageManager. No PluginManager on Velocity.

## Testing notes

- Tests are under `src/test/java/io/omnibrige/` — `core/` (5 classes), `download/` (3 classes), and `config/` (1 class)
- No integration tests — all tests are pure unit tests that don't need a Minecraft server
- `RepositoryUrlsTest` is tagged `network` and excluded from the default build via `<excludedGroups>network</excludedGroups>` in `pom.xml`
- `MessageManagerTest.allLocalesResolveMessagesWithoutKeyLeaks()` iterates 71 non-default locales and verifies the fallback contract
- `RepositoryTest.dependenciesAreCorrect()` and `jarNamesAreCorrect()` are the ground truth for plugin metadata
- `PluginManagerTest` covers `compareVersions` (numeric comparison, snapshot suffixes, unparseable input)
