# OmniBridge — Agent Guide

## Build & Test

```bash
mvn clean package                  # produces target/OmniBridge-1.0.0.jar
mvn test                           # run all 6 test classes
mvn test -Dtest=RepositoryTest     # single test class
```

Uses **Maven** (no wrapper), **Java 21**, **JUnit 5.10.2**. No mocking framework — tests are pure unit tests.

CI: GitHub Actions — `build.yml` (`mvn clean package -q`) on push to `main`/`dev` and PR to `main`. Release: tag `v*` triggers `release.yml`.

## Architecture

**Dual entry point** — the same JAR acts as both a Bukkit plugin and a Velocity plugin:

| Platform | Main class | Descriptor |
|---|---|---|
| Paper/Spigot | `io.omnibrige.OmniBridge` | `plugin.yml` |
| Velocity | `io.omnibrige.OmniBridgeVelocity` | `velocity-plugin.json` |

Platform detection (`PlatformDetector.detect()`): checks Velocity first (class `com.velocitypowered.api.proxy.ProxyServer`), then Paper, Fabric, Spigot.

**Key packages:**
- `io.omnibrige.api` — public API (`OmniBridgeAPI`, events, `ViaVersionIntegration`, `GeyserIntegration`)
- `io.omnibrige.core` — `PluginManager`, `ConfigManager`, `MessageManager`, `PlatformDetector`, `PluginPresets`, `PluginDescriptions`
- `io.omnibrige.download` — `Repository` (hardcoded plugin registry of 24+ plugins with URLs), `DownloadService`
- `io.omnibrige.config` — per-plugin config generators (ViaVersion, ViaBackwards, ViaRewind, Geyser, Floodgate, ViaRewindLegacySupport)
- `io.omnibrige.commands` — `OmniBridgeCommand` (Bukkit), `OmniBridgeCommandVelocity`, `ChatConfigMenu`

## Key facts

- **Command base**: `/omnibrige` — aliases `ob` and `omnib` (defined in `plugin.yml`)
- **Plugin registry** is in `Repository.java` (static initializer block) — all download URLs, JAR names, Bukkit names, and dependency mappings are hardcoded there. Update URLs there when bumping plugin versions. Currently 29 plugins. When adding a new plugin, also add its description to `PluginDescriptions.java` and a config entry in `config.yml`.
- **Dependency auto-resolution**: enabling Geyser auto-enables Floodgate; enabling AuthMe also auto-enables Floodgate; DiscordSRV requires PlaceholderAPI; TuffXPlus requires ViaVersion+ViaBackwards.
- **Platform compatibility**: ViaBungee only on Velocity; ProtocolLib and TuffXPlus only on Bukkit-based platforms; others universal.
- **Configs**: `config.yml` at plugin root; per-plugin configs generated by `ConfigManager` only for ViaVersion/ViaBackwards/ViaRewind/ViaRewindLegacySupport/Geyser/Floodgate. Methods in `io.omnibrige.config.*` write defaults (won't overwrite existing files).
- **Locale**: 72 YAML files in `src/main/resources/locale/`. `MessageManager` loads by locale code (e.g. `en_US`, `tr_TR`). Fallback: returns the message key if not found.
- **Presets**: 7 predefined bundles (`bedrock`, `full-version`, `essentials`, `server-essentials`, `max-compat`, `performance`, `chat`) in `PluginPresets.java`.
- **Events**: Custom Bukkit events (`PluginInstalledEvent`, `PluginRemovedEvent`, `PluginUpdatedEvent`) in `io.omnibrige.api.events`.
- **Build artifact**: `target/OmniBridge-1.0.0.jar` (gitignored). Server install: drop into `plugins/` folder.
- **Velocity support is limited**: only registers a command and initializes MessageManager. No PluginManager on Velocity.

## Testing notes

- Tests are under `src/test/java/io/omnibrige/` — `core/` (4 classes), `download/` (2 classes), and `config/` (1 class)
- No integration tests — all tests are pure unit tests that don't need a Minecraft server
- `MessageManagerTest.allLocalesLoadSuccessfully()` iterates 71 locales and verifies translations exist
- `RepositoryTest.dependenciesAreCorrect()` and `jarNamesAreCorrect()` are the ground truth for plugin metadata
